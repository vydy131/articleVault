# Материалы эксперимента

Приложение к статье «Экспериментальное исследование влияния больших языковых моделей на скорость и качество декомпозиции программных приложений».

## Проверка опубликованных результатов

Скриптам анализа достаточно стандартной библиотеки Python 3.12. Запускайте команды из каталога с распакованными файлами.

```sh
python3 analysis.py
python3 metrics.py
```

Первый скрипт воспроизводит показатели назначения классов модулям, время и тест устойчивости к порядку вариантов (таблицы 3 и 4). Второй воспроизводит ARI и время формирования групп без размеченных примеров (таблица 2). В итоговом столбце времени складываются медианы по трём приложениям. Для базового TF-IDF в таблице 3 взяты три запуска из серии с Qwen 1.5B.

* `data.json` — исходные карточки, английские описания модулей, размеченные примеры и тестовые случаи. Поле `n` содержит число подходящих классов в модуле до отбора.
* `results.json`, `small-results.json` — распределения по известным модулям и измерения времени для серий Qwen 1.5B и 0.5B. Поле `calls` показывает число проверочных карточек, для которых вычислялись оценки модели.
* `grouping-results.json` — назначения в группы без известных названий, их времена и номера повторов. Каждая буква обозначает одну группу внутри одного запуска.
* `rotation-big.json`, `rotation-small.json` — предсказания при двух циклических сдвигах. Нулевой сдвиг берётся из основной серии.
* `predictions.csv` — эталон и назначения для всех 45 классов в основном порядке. У свободно сформированных групп буквы произвольны. Для чтения кириллического текста используется UTF-8.
* Значения времени в JSON указаны в секундах. Все эталонные и предсказанные принадлежности можно проверить без подключения к сети.

## Повторение измерений

Для новых запусков распакуйте приложение в отдельный каталог. Скрипты записывают новые наблюдения в одноимённые JSON-файлы. В исходном эксперименте использованы Python 3.12.3, llama-cpp-python 0.3.16, CPU Intel Core i5-10200H, 4 потока, квантование Q4_K_M и `OPENBLAS_NUM_THREADS=1`. Между карточками в сценарии известных модулей сохраняется общий префикс запроса. Загружаемые веса моделей вместе займут около 1,6 ГБ.

### Исходный код приложений

Для повторного извлечения карточек загрузите архивы открытых репозиториев. Готовые карточки в `data.json` уже позволяют выполнить модельные прогоны.

```sh
curl -fL https://codeload.github.com/saleor/saleor/tar.gz/1ce97784dcdc073be328ae9bc1179ccb915e831d -o saleor.tar.gz

```

### Модели и запуски

```sh
curl -fL https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/resolve/9217f5db79a29953eb74d5343926648285ec7e67/qwen2.5-0.5b-instruct-q4_k_m.gguf -o small.gguf
curl -fL https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/91cad51170dc346986eccefdc2dd33a9da36ead9/qwen2.5-1.5b-instruct-q4_k_m.gguf -o model.gguf
sha256sum -c weights.sha256
python3 -m venv .venv
. .venv/bin/activate
CMAKE_ARGS='-DGGML_NATIVE=OFF -DGGML_BLAS=OFF -DGGML_CUDA=OFF' python -m pip install llama-cpp-python==0.3.16
export OPENBLAS_NUM_THREADS=1
python bench.py --size 1.5
python rotate.py big
python bench.py --size 0.5
python rotate.py small
python grouping.py
python analysis.py
python metrics.py
```

`samples.py` фиксирует отбор классов по хешу. В `bench.py` и `grouping.py` приведены точные английские инструкции и логика выбора токенов. В обоих лексических вариантах используется частота слова, умноженная на сглаженный вес IDF, с нормированием вектора. Для известного модуля документом служит его описание вместе с двумя примерами. Для группировки отдельным документом служит карточка класса. В `rotate.py` переставляются и описания, и примеры, поэтому меняется только позиция вариантов в запросе. Скорость повторного прогона зависит от устройства и текущей нагрузки.
